# 5차 호출 프롬프트 (A/B 테스트 평가)

나는 동일한 조건에서 생성된 `원본 테스트 대화`와 `개선 테스트 대화`를 비교하여 캐릭터 챗 프롬프트 개선 효과를 평가하려고 한다.

아래의 `개선 요청 사항`, `개선 목표`, `금지 사항`, `원본 테스트 대화`, `개선 테스트 대화`를 참고하여 각 대화를 동일한 기준으로 측정하고 A/B 테스트 결과를 평가하라.

이 단계에서는 테스트 대화를 새로 생성하거나 수정하지 않는다. `개선 프롬프트`나 `개선 인트로 대화`를 다시 작성하지도 않는다. 입력된 `원본 테스트 대화` 및 `개선 테스트 대화`에서 실제로 확인할 수 있는 내용만을 근거로 평가한다.

평가 과정에서는 먼저 `개선 목표`와 `금지 사항`을 기계적으로 판정할 수 있는 평가 기준으로 변환한 뒤, `원본 테스트 대화`와 `개선 테스트 대화`의 지표를 비교한다. 이후 절대적인 목표 달성 여부와 `원본 테스트 대화` 대비 `개선 테스트 대화`의 개선 정도를 함께 고려하여 `개선 성공 여부`, `잔존 문제`, `재수정 필요 여부`를 판단한다.

## 평가 원칙

1. `개선 요청 사항`은 이번 평가의 대상과 범위를 정하는 기준으로 사용한다.
2. `개선 목표`는 `개선 테스트 대화`가 반드시 충족해야 하는 절대 평가 기준으로 사용한다.
3. `금지 사항`은 `원본 테스트 대화`와 `개선 테스트 대화`에서 문제 출력이 발생했는지 판단하는 위반 기준으로 사용한다.
4. `원본 테스트 대화`와 `개선 테스트 대화`에 동일한 평가 기준을 적용한다.
5. `개선 테스트 대화`에만 유리하거나 `원본 테스트 대화`에만 불리한 기준을 임의로 추가하지 않는다.
6. 입력된 `원본 테스트 대화` 및 `개선 테스트 대화`에서 직접 확인할 수 없는 캐릭터 의도, 모델의 내부 판단과 생성 원인은 추측하지 않는다.
7. `개선 요청 사항`, `개선 목표`, `금지 사항`과 직접 관련 없는 새로운 문제를 평가 기준에 추가하지 않는다.
8. 문체에 대한 개인적인 선호보다 측정 가능한 결과와 명시된 기준을 우선한다.
9. `원본 테스트 대화`가 길거나 과장되어 보인다는 이유만으로 자동으로 실패 처리하지 않는다. 각 기준에 따라 실제 수치와 위반 여부를 확인한다.
10. `개선 테스트 대화`가 원본보다 짧다는 이유만으로 자동으로 성공 처리하지 않는다. `개선 목표`를 충족했는지 별도로 확인한다.
11. 테스트 대화 간 자연스러운 생성 편차를 고려하되, 동일한 문제가 여러 대화에서 반복되면 프롬프트의 안정성 문제로 판단한다.
12. 평가 결과가 불분명하면 임의로 성공 또는 실패로 단정하지 않고 `판정 유보`로 표시한다.

## 1. 입력 유효성 확인

평가 전에 다음 내용을 내부적으로 확인한다.

- `원본 테스트 대화`가 3개 모두 입력되었는가?
- `개선 테스트 대화`가 3개 모두 입력되었는가?
- 각 테스트 대화가 서로 독립적인 결과로 구분되어 있는가?
- `원본 테스트 대화`와 `개선 테스트 대화`가 동일한 사용자 입력에 대한 응답으로 보이는가?
- 테스트 대화 중 일부가 중간에 잘렸거나 비어 있지 않은가?

평가에 필요한 대화가 누락되거나 비교 조건이 명백히 다르면 결과를 임의로 보완하지 않는다. 이 경우 `개선 성공 여부`를 `판정 유보`로 작성하고, 누락된 조건을 `잔존 문제`와 `재수정 필요 여부`에 명시한다.

## 2. 기계적 평가 기준 도출

`개선 목표`와 `금지 사항`을 각 대화에서 동일하게 확인할 수 있는 평가 지표로 변환한다.

기계적 평가 기준을 별도의 분석 항목으로 출력하지는 않으며, `원본과 개선본의 지표 비교` 표의 `평가 지표`와 `판정 기준`에 간결하게 표시한다.

### 개선 목표 변환

각 `개선 목표`를 다음 요소로 구조화한다.

- 평가 지표
- 측정 단위
- 통과 기준
- 대화별 측정값
- 대화별 통과 또는 실패

예시:

- 개선 목표: 하나의 응답에서 내레이션은 최대 3문장
- 평가 지표: 응답당 내레이션 문장 최대 수
- 측정 단위: 문장
- 통과 기준: 각 응답 최대 3문장
- 개선 목표: 연속된 내레이션 블록은 최대 2개
- 평가 지표: 응답당 연속 내레이션 블록 최대 수
- 측정 단위: 블록
- 통과 기준: 각 응답 최대 2개
- 개선 목표: 직접 해설하는 인물의 내면은 최대 1명
- 평가 지표: 응답당 직접 내면 해설 인물 최대 수
- 측정 단위: 명
- 통과 기준: 각 응답 최대 1명

수치가 있는 `개선 목표`는 입력된 수치를 그대로 사용한다. 임의로 기준을 더 강하거나 느슨하게 변경하지 않는다.

수치가 없는 `개선 목표`는 실제 대화에서 관찰할 수 있는 예·아니요 기준이나 위반 횟수로 변환한다.

### 금지 사항 변환

각 `금지 사항`은 대화별 위반 여부와 위반 횟수로 측정한다.

- 위반이 없으면 0회로 측정하고 통과 처리한다.
- 한 번 이상 나타나면 실제 위반 횟수를 측정하고 실패 처리한다.
- 하나의 구간이 여러 금지 사항에 동시에 해당하면 각 기준에서 각각 판정할 수 있다.
- 같은 표현이 명백하게 이어지는 하나의 묘사라면 문장을 나누었다는 이유만으로 중복 집계하지 않는다.
- 서로 다른 문장이나 문단에서 동일한 문제 행동이나 표현이 다시 발생하면 별도의 위반으로 집계한다.

예시:

- 금지 사항: 동일한 감정을 표현을 바꾸어 두 번 이상 설명
- 평가 지표: 반복 감정 설명
- 판정 기준: 위반 0회
- 금지 사항: 세 인물의 내면을 차례로 모두 해설
- 평가 지표: 다중 인물 내면 해설
- 판정 기준: 위반 0회
- 금지 사항: 대사의 앞뒤에 내레이션을 반복 삽입
- 평가 지표: 반복적인 대사 경계 내레이션 삽입
- 판정 기준: 위반 0회

### 표 입력 형식 통일

`원본과 개선본의 지표 비교` 표는 다음 규칙에 따라 작성한다.

#### 평가 지표

- 실제로 측정하는 행동이나 출력 현상을 간결하게 작성한다.
- 하나의 행에는 하나의 평가 기준만 포함한다.
- 평가 지표 안에 판정 결과나 대화별 사례를 작성하지 않는다.

좋은 예:

- 응답당 위치·일정·연락 확인·보고 요구 최대 횟수
- 사전 합의 없는 직장 방문·대기 또는 귀가 강제
- 가벼운 감정으로 발생한 파괴적 마력 분출

나쁜 예:

- 위치를 계속 물어보고 집 앞까지 찾아오는 문제
- 대화 1에서 발생한 직장 방문
- 원본에는 많지만 개선본에는 없어진 마력 폭주

#### 판정 기준

- 수치와 허용 조건만 간결하게 작성한다.
- 사례, 원인, 장면 설명, 해석을 포함하지 않는다.
- 가능한 경우 `최대 N회`, `N회 이하`, `위반 0회`, `각 응답 최대 N개` 형식으로 작성한다.

좋은 예:

- 각 응답 최대 1회
- 동일 응답 내 0회
- 위반 0회
- 각 응답 최대 3문장
- 파괴 반응 없이 최대 1개

나쁜 예:

- 기대나 떨림 같은 가벼운 감정만으로 발생하면 안 됨
- 파괴가 일어났다면 위험한 상황이어야 함
- 캐릭터가 상대방의 선택을 존중해야 함

판정 기준의 의미를 유지하면서도 가능한 한 수치형 또는 예·아니요형 기준으로 압축한다.

#### 개별 테스트 대화 셀

각 `원본 테스트 대화 1~3` 및 `개선 테스트 대화 1~3` 셀에는 측정값과 판정만 작성한다.

기본 형식:

- `0회(통과)`
- `1회(실패)`
- `최대 2회(실패)`
- `2개(통과)`
- `최대 5문장(실패)`
- `2명(실패)`

다음 규칙을 지킨다.

1. 측정값 뒤에 반드시 `(통과)` 또는 `(실패)`를 표시한다.
2. 금지 사항이 발생하지 않은 경우 `0회(통과)`로 작성한다.
3. 조건이 발동하지 않았더라도 위반이 없다면 `0회(통과)`로 작성한다.
4. `위반`, `성공`, `충족`, `조건 미발동` 등 다른 판정 표현을 섞지 않는다.
5. 위반 장면, 원인, 행동 사례, 인용문을 개별 테스트 대화 셀에 작성하지 않는다.
6. `1회: 충격파·기물 파괴(실패)`처럼 측정값 뒤에 사례를 붙이지 않는다.
7. `폭주 없음: 조건 미발동(통과)`처럼 설명형 문장을 작성하지 않는다.
8. 하나의 대화에 여러 응답이 있는 최대치 기준이라면 `최대 N회(통과/실패)`로 작성한다.
9. 대화 전체의 누적 발생 횟수를 측정하는 기준이라면 `N회(통과/실패)`로 작성한다.
10. 측정 단위가 회가 아니면 지표에 맞는 단위를 사용한다.

예시:

- 최대 횟수 기준: `최대 2회(실패)`
- 누적 위반 기준: `4회(실패)`
- 문장 수 기준: `최대 5문장(실패)`
- 인물 수 기준: `2명(실패)`
- 비율 기준: `75%(실패)`

#### 원본 종합 및 개선본 종합 셀

종합 셀은 개별 대화 3개의 결과를 정량적으로 집계하여 작성한다.

누적 횟수형 지표의 기본 형식:

`총 N회, 평균 N.N회, 통과 X/3`

예시:

- `총 9회, 평균 3.0회, 통과 0/3`
- `총 0회, 평균 0.0회, 통과 3/3`
- `총 2회, 평균 0.7회, 통과 1/3`

응답당 최대치처럼 각 대화의 최댓값을 비교하는 지표는 다음 형식을 사용한다.

`평균 N.N회, 범위 A~B회, 통과 X/3`

예시:

- `평균 2.7회, 범위 2~3회, 통과 0/3`
- `평균 0.3회, 범위 0~1회, 통과 3/3`

다음 규칙을 지킨다.

1. 누적 횟수를 측정할 수 있는 지표는 `총합 → 평균 → 통과 수` 순서로 작성한다.
2. 각 대화의 최댓값을 측정하는 지표는 `평균 → 범위 → 통과 수` 순서로 작성한다.
3. 평균은 소수점 첫째 자리까지 작성한다.
4. 평균이 정수라도 `3.0회`, `0.0회`처럼 소수점 첫째 자리를 유지한다.
5. 마지막에는 반드시 `통과 X/3`을 작성한다.
6. `위반 대화 3/3`, `발생 응답 2/3`, `모두 위험 요인 미명시` 등 서로 다른 형식을 섞지 않는다.
7. 종합 셀에 개별 사례나 장면 설명을 작성하지 않는다.
8. 측정 단위가 회가 아니면 해당 단위를 일관되게 사용한다.

#### 변화 및 비교 셀

`변화 및 비교`에는 원본 종합과 개선본 종합의 차이를 간결하게 작성한다.

기본 구성:

1. 전체 발생 횟수 또는 평균 측정값의 증감
2. 통과 대화 수의 변화
3. 필요한 경우 문제 행동의 제거 또는 잔존 여부

좋은 예:

- `총 9회 감소. 통과 0/3 → 3/3`
- `평균 최대 횟수 2.4회 감소. 기준 초과 대화 3/3 → 0/3`
- `총 11회 감소. 방문·대기·확인 행동이 모두 제거됨`
- `총 2회 감소. 통과 1/3 → 3/3`
- `변화 없음. 원본과 개선본 모두 통과 3/3`

다음 규칙을 지킨다.

1. 원본과 개선본의 수치를 모두 확인할 수 있도록 작성한다.
2. `좋아짐`, `크게 개선됨`, `안정적임`처럼 수치 없는 평가만 작성하지 않는다.
3. 사례를 길게 나열하지 않는다.
4. 한 문장 또는 두 개의 짧은 문장으로 작성한다.
5. 감소량을 계산할 수 있으면 `총 N회 감소`, `평균 N.N회 감소`처럼 절대 변화량을 작성한다.
6. 통과 수가 달라졌으면 `통과 X/3 → Y/3`을 함께 작성한다.
7. 모든 개선 대화에서 문제가 제거된 경우에만 `모두 제거됨`이라고 작성한다.
8. 원본보다 감소했지만 개선본에 위반이 남아 있다면 제거되었다고 표현하지 않는다.

## 3. 대화별 독립 평가

`원본 테스트 대화` 3개와 `개선 테스트 대화` 3개를 각각 독립적으로 평가한다.

각 대화에 대해 다음 내용을 내부적으로 기록한다.

- 각 `개선 목표`의 측정값
- 각 `개선 목표`의 통과 또는 실패
- 각 `금지 사항`의 위반 횟수
- 전체 `개선 목표` 통과 여부
- `금지 사항` 전체 통과 여부

대화 하나에서 기준을 위반했다고 해서 같은 테스트 대화 그룹의 다른 대화도 자동으로 실패 처리하지 않는다. 반대로 대화 하나가 모든 기준을 충족했다고 해서 해당 테스트 대화 그룹 전체를 성공 처리하지 않는다.

표의 개별 테스트 대화 셀에는 내부적으로 확인한 사례나 근거를 모두 옮기지 않는다. 최종 표에는 측정값과 `(통과)` 또는 `(실패)`만 작성한다.

## 4. 그룹별 지표 집계

원본 테스트 대화 그룹과 개선 테스트 대화 그룹 각각에 대해 다음 값을 집계한다.

### 누적 횟수형 지표

- 대화 1, 2, 3의 개별 발생 횟수
- 세 대화의 전체 발생 횟수
- 대화당 평균 발생 횟수
- 기준을 통과한 대화 수

종합 셀 형식:

`총 N회, 평균 N.N회, 통과 X/3`

예시:

- 원본 종합: `총 9회, 평균 3.0회, 통과 0/3`
- 개선본 종합: `총 0회, 평균 0.0회, 통과 3/3`

### 최대치형 지표

각 대화에 여러 응답이 있으며 응답별 최대 횟수나 최대 문장 수를 판단하는 경우 다음 값을 집계한다.

- 각 대화에서 확인된 최댓값
- 세 대화 최댓값의 평균
- 세 대화 최댓값의 최솟값과 최댓값
- 기준을 통과한 대화 수

종합 셀 형식:

`평균 N.N회, 범위 A~B회, 통과 X/3`

예시:

- 원본 종합: `평균 2.7회, 범위 2~3회, 통과 0/3`
- 개선본 종합: `평균 0.3회, 범위 0~1회, 통과 3/3`

### 다른 단위의 지표

문장, 블록, 명, 개, 비율 등 다른 단위를 사용하는 경우에도 같은 형식을 유지한다.

예시:

- `평균 5.3문장, 범위 4~7문장, 통과 0/3`
- `총 4개, 평균 1.3개, 통과 1/3`
- `평균 1.7명, 범위 1~2명, 통과 1/3`

### 변화량 산출

계산 가능한 경우 원본 테스트 대화 그룹 대비 개선 테스트 대화 그룹의 절대 변화량을 산출한다.

예시:

- `평균 최대 문장 수 6.0문장 감소. 통과 0/3 → 3/3`
- `총 위반 4회 감소. 통과 1/3 → 3/3`
- `총 위반 9회 감소. 모든 개선 대화에서 기준을 충족함`

백분율이 의미 있는 경우에만 증감률을 사용한다. 기준값이 0이거나 표본이 작아 오해를 일으킬 수 있으면 절대 변화량만 작성한다.

## 5. 원본과 개선본 비교

각 지표에 대해 다음 세 가지를 함께 판단한다.

### 절대 평가

개선 테스트 대화가 `개선 목표`와 `금지 사항`을 충족했는지 판단한다.

### 상대 평가

개선 테스트 대화가 원본 테스트 대화보다 문제 지표를 줄였는지 판단한다.

### 안정성 평가

개선 효과가 개선 테스트 대화 3개에서 일관되게 나타나는지 판단한다.

예시:

- 개선 대화 3개 모두 목표 충족: 안정적으로 충족
- 개선 대화 2개만 목표 충족: 일부 편차 존재
- 개선 대화 1개 이하만 목표 충족: 불안정
- 평균은 개선됐지만 한 대화에서 크게 위반: 평균 개선, 안정성 부족

## 6. 개선 성공 여부 판정

`개선 성공 여부`는 다음 중 하나로 판정한다.

### 성공

다음 조건을 모두 충족한 경우다.

- 개선 테스트 대화 3개가 모든 핵심 `개선 목표`를 충족함
- 개선 테스트 대화 3개에서 `금지 사항` 위반이 발생하지 않음
- 원본 테스트 대화보다 개선 테스트 대화에서 핵심 문제 지표가 개선되었거나, 원본 테스트 대화가 이미 기준을 충족한 경우에도 성능 저하가 없음
- 개선 효과가 특정 응답 하나에만 나타나지 않고 안정적으로 유지됨

### 부분 성공

다음 중 하나에 해당하는 경우다.

- 원본 테스트 대화보다 핵심 지표가 개선되었지만 개선 테스트 대화 중 일부가 목표를 위반함
- 개선 목표는 대부분 충족했지만 일부 금지 사항이 남아 있음
- 평균은 개선되었지만 대화 간 편차가 큼
- 여러 개선 목표 중 일부만 충족함

### 실패

다음 중 하나에 해당하는 경우다.

- 원본 테스트 대화와 비교해 핵심 문제 지표가 의미 있게 개선되지 않음
- 개선 테스트 대화가 원본 테스트 대화보다 악화됨
- 개선 테스트 대화 3개 중 2개 이상이 핵심 `개선 목표`를 위반함
- `금지 사항`이 개선 테스트 대화에서 반복적으로 발생함
- 문제 표현만 달라졌을 뿐 동일한 문제 현상이 유지됨

### 판정 유보

다음 중 하나에 해당하는 경우다.

- 원본 또는 개선 테스트 대화가 누락됨
- 원본과 개선 테스트 대화의 테스트 조건이 동일하지 않음
- 테스트 대화가 잘려 있어 정확한 측정이 불가능함
- 원본 테스트 대화가 이미 모든 `개선 목표`를 충족해 상대적인 개선 효과를 확인하기 어려움
- 입력된 기준이 서로 충돌하거나 관찰 가능한 형태로 해석할 수 없음

판정은 원본 대비 변화만으로 결정하지 않는다. 개선 테스트 대화가 원본 테스트 대화보다 나아졌더라도 절대적인 `개선 목표`를 충족하지 못하면 `성공`이 아니라 `부분 성공`으로 판단한다.

## 7. 잔존 문제 판단

`잔존 문제`에는 개선 테스트 대화에서 여전히 발견되는 `문제 현상`만 작성한다.

다음 내용을 포함한다.

- 충족하지 못한 `개선 목표`
- 반복해서 발생한 `금지 사항`
- 특정 테스트 대화에서만 나타난 불안정한 위반
- 평균은 개선됐지만 최댓값이 목표를 크게 넘는 문제
- 원본 테스트 대화와 표현만 달라졌을 뿐 남아 있는 동일한 `문제 현상`

각 잔존 문제에는 가능하면 다음 내용을 함께 작성한다.

- 해당 지표
- 문제 현상이 나타난 개선 테스트 대화 번호
- 실제 측정값 또는 위반 횟수
- `개선 목표` 기준과의 차이

예시:

- 개선 테스트 대화 2의 내레이션이 최대 5문장으로, 기준인 최대 3문장을 2문장 초과함.
- 개선 테스트 대화 1과 3에서 독현과 지아의 내면을 모두 해설해 내면 해설 인물 수 기준을 위반함.

`개선 요청 사항`과 관계없는 새로운 문제를 잔존 문제로 추가하지 않는다.

잔존 문제가 없으면 `확인된 잔존 문제 없음`으로 작성한다.

## 8. 재수정 필요 여부 판단

`재수정 필요 여부`는 다음 중 하나로 판정한다.

### 불필요

- `개선 성공 여부`가 성공임
- 개선 테스트 대화 3개가 핵심 `개선 목표`와 `금지 사항`을 안정적으로 충족함
- 확인된 `잔존 문제`가 없음

### 권장

- `개선 성공 여부`가 부분 성공임
- 개선 효과는 확인되지만 개선 테스트 대화 중 1개 이상에서 `개선 목표` 위반이나 `금지 사항`이 발생함
- 평균은 개선됐으나 개선 테스트 대화 간 편차가 남아 있음
- 핵심 `문제 현상`은 줄었지만 일부 잔존 문제가 있음

### 필수

- `개선 성공 여부`가 실패임
- 개선 테스트 대화 3개 중 2개 이상에서 핵심 문제가 반복됨
- `개선 목표`가 대부분 충족되지 않음
- `금지 사항`이 반복적으로 발생함
- 개선 테스트 대화가 원본 테스트 대화와 차이가 없거나 더 악화됨

### 판단 보류

- `개선 성공 여부`가 판정 유보임
- 비교 가능한 테스트 대화 데이터가 부족하거나 테스트 조건이 일치하지 않음

재수정 필요 여부를 판단할 때 추가 개선 프롬프트의 구체적인 수정안을 작성하지 않는다. 다시 수정해야 할 필요성과 잔존한 평가 기준만 명시한다.

## 9. 출력 전 자체 검증

최종 결과를 출력하기 전에 내부적으로 다음 내용을 확인한다. 검증 과정은 출력하지 않는다.

### 평가 기준 검증

- 모든 `개선 목표`가 평가 지표에 반영되었는가?
- 모든 `금지 사항`의 위반 여부를 확인했는가?
- 원본 테스트 대화와 개선 테스트 대화에 동일한 기준을 적용했는가?
- `개선 요청 사항`과 관계없는 기준을 추가하지 않았는가?

### 측정 검증

- 테스트 대화별 측정값을 일관된 방식으로 계산했는가?
- 내레이션과 대사를 동일한 기준으로 구분했는가?
- 같은 표현을 중복으로 과도하게 집계하지 않았는가?
- 수치가 불확실한 부분을 임의로 정확한 값처럼 작성하지 않았는가?
- 개별 테스트 대화 셀이 `측정값(통과/실패)` 형식으로 작성되었는가?
- 개별 테스트 대화 셀에 장면 설명이나 위반 사례가 포함되지 않았는가?
- 누적 횟수형 종합 셀이 `총합, 평균, 통과 수` 순서로 작성되었는가?
- 최대치형 종합 셀이 `평균, 범위, 통과 수` 순서로 작성되었는가?
- 모든 종합 셀에 `통과 X/3`이 포함되었는가?
- 평균값이 소수점 첫째 자리까지 작성되었는가?
- `판정 기준`이 수치 또는 간결한 허용 조건으로 작성되었는가?
- `변화 및 비교`가 정량적인 증감과 통과 수 변화를 포함하는가?

### 판정 검증

- 상대적으로 개선됐다는 이유만으로 절대 `개선 목표` 미달을 성공 처리하지 않았는가?
- 개선 테스트 대화의 일부 위반을 평균값으로 숨기지 않았는가?
- 대화 하나의 결과만으로 전체 개선 테스트 대화 그룹을 판단하지 않았는가?
- 개선 테스트 대화를 의도적으로 유리하게 해석하지 않았는가?
- 성공 여부와 재수정 필요 여부가 서로 모순되지 않는가?

기준을 충족하지 못한 부분이 있으면 다시 측정하고 판정한 뒤 최종 결과만 출력한다.

## 출력 규칙

1. `원본과 개선본의 지표 비교`를 먼저 출력한다.
2. 그다음 `개선 성공 여부`, `잔존 문제`, `재수정 필요 여부` 순서로 출력한다.
3. 기계적 평가 기준을 별도의 독립된 장으로 출력하지 않는다.
4. 대화 원문 전체를 다시 출력하지 않는다.
5. 테스트 대화를 수정하거나 더 나은 테스트 대화 예시를 작성하지 않는다.
6. `최종 개선 프롬프트`나 `최종 개선 인트로 대화`의 수정안을 작성하지 않는다.
7. 문제 진단 과정과 장황한 분석을 출력하지 않는다.
8. 모든 판단에는 측정값, 위반 대화 수 또는 구체적인 근거를 포함한다.
9. `개선 요청 사항`과 관계없는 문제를 추가 평가하지 않는다.
10. 입력에 없는 사실을 임의로 만들어 평가하지 않는다.
11. 표의 `판정 기준`에는 통과 기준만 간결하게 작성하고 장면 설명이나 사례를 포함하지 않는다.
12. 표의 개별 테스트 대화 셀에는 측정값과 `(통과)` 또는 `(실패)`만 작성한다.
13. 개별 테스트 대화 셀에 원문 인용, 위반 사례, 원인, 해설을 작성하지 않는다.
14. 금지 사항이 발생하지 않았거나 조건이 발동하지 않은 경우에도 `0회(통과)`로 작성한다.
15. 누적 횟수형 지표의 종합 셀은 `총 N회, 평균 N.N회, 통과 X/3` 형식으로 작성한다.
16. 최대치형 지표의 종합 셀은 `평균 N.N회, 범위 A~B회, 통과 X/3` 형식으로 작성한다.
17. 종합 셀에 `위반 대화 X/3`, `발생 응답 X/3`처럼 별도의 표현을 사용하지 않는다.
18. `변화 및 비교`에는 총합 또는 평균의 절대 변화량과 통과 대화 수의 변화를 우선 작성한다.
19. 모든 표 행에서 동일한 표기 순서와 측정 단위를 유지한다.
20. 표 안에서는 `통과/실패` 외의 판정 표현을 혼용하지 않는다.
