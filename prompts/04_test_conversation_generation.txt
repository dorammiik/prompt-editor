# 4차 호출 프롬프트 

나는 캐릭터챗의 `원본 프롬프트`와 `최종 개선 프롬프트`가 동일한 상황에서 어떻게 작동하는지 확인하기 위해 테스트 응답을 생성하려고 한다.

아래의 `개선 요청 사항`, `원본 프롬프트`, `원본 인트로 대화`, `최종 개선 프롬프트`, `최종 개선 인트로 대화`, `테스트 직전 대화 맥락`, `테스트 사용자 입력`을 사용하여 `원본 테스트 대화` 3개와 `개선 테스트 대화` 3개를 생성하라.

`개선 요청 사항`이 하나의 대화만으로 문제를 확인할 수 있는 유형이라면 각 테스트 대화에서 `테스트 사용자 입력`에 대한 대화 1개를 생성하고, 이러한 유형을 `단일 대화 테스트`라고 한다.

`개선 요청 사항`이 여러개의 대화에서 변화와 흐름을 확인해야 하는 유형이라면 `테스트 사용자 입력`을 첫 번째 사용자 입력으로 사용하고, 이후 사용자 입력은 모델이 자연스럽게 생성하여 각 테스트 대화를 총 8라운드까지 이어간다. 이러한 유형을 `장기 대화 테스트`라고 하며, 1라운드 이후 모델이 자연스럽게 생성한 사용자 입력을 `후속 사용자 입력`이라고 한다. 한 라운드는 사용자 입력 1개와 이후 대화 1개로 구성한다.

`장기 대화 테스트`에서는 같은 번호의 `원본 테스트 대화`와 `개선 테스트 대화`에 동일한 후속 사용자 입력을 사용한다. 예를 들어 `원본 테스트 대화 1`과 `개선 테스트 대화 1`은 첫 번째 입력뿐 아니라 이후 생성된 사용자 입력도 동일해야 한다.

`원본 테스트 대화`는 모두 동일한 `원본 프롬프트`, 동일한 `원본 인트로 대화`, 동일한 직전 대화 맥락과 동일한 첫 번째 사용자 입력에서 각각 독립적으로 생성된 테스트 대화이어야 한다.

`개선 테스트 대화`는 모두 동일한 `최종 개선 프롬프트`, 동일한 `최종 개선 인트로 대화`, 동일한 직전 대화 맥락과 동일한 첫 번째 사용자 입력에서 각각 독립적으로 생성된 테스트 대화이어야 한다.

각 테스트 대화는 하나의 대화에서 연속으로 이어지는 대화가 아니다. `원본 테스트 대화`와 `개선 테스트 대화` 모두 동일한 `테스트 직전 대화 맥락`과 `테스트 사용자 입력`을 사용한다.

이 단계에서는 테스트 대화를 평가하거나 수정 방향을 제안하지 않는다. `원본 프롬프트`와 `최종 개선 프롬프트`를 실제 캐릭터챗에 적용했을 때 생성될 수 있는 테스트 대화 원문을 만드는 데 집중한다.

## 테스트 원칙

1. 모든 `원본 테스트 대화`에 동일한 `원본 프롬프트`를 적용한다.
2. 모든 `원본 테스트 대화`에 동일한 `원본 인트로 대화`를 적용한다.
3. 모든 `개선 테스트 대화`에 동일한 `최종 개선 프롬프트`를 적용한다.
4. 모든 `개선 테스트 대화`에 동일한 `최종 개선 인트로 대화`를 적용한다.
5. 모든 원본 및 개선 테스트 대화에 동일한 `테스트 직전 대화 맥락`을 적용한다.
6. 모든 원본 및 개선 테스트 대화의 첫 번째 캐릭터 응답은 입력된 `테스트 사용자 입력`에 직접 이어지는 답변으로 작성한다.
7. `테스트 사용자 입력`의 문장, 의미, 말투와 정보를 임의로 수정하거나 보완하지 않는다.
8. 각 원본 및 개선 테스트 대화는 다른 테스트 대화와 독립적으로 생성한다.
9. 앞에서 생성한 테스트 대화의 사건, 대사, 표현과 관계 변화를 다음 테스트 대화에 이어서 사용하지 않는다.
10. 테스트 대화를 서로 다르게 만들기 위해 캐릭터 설정, 관계 단계, 세계관과 출력 규칙을 바꾸지 않는다.
11. 자연스럽게 발생하는 표현과 행동의 차이는 허용하지만, 의도적으로 서로 다른 문체나 극단적인 전개를 강제하지 않는다.
12. `원본 테스트 대화`에는 `원본 프롬프트`에 없는 인물, 사건, 관계와 설정을 추가하지 않는다.
13. `개선 테스트 대화`에는 `최종 개선 프롬프트`에 없는 인물, 사건, 관계와 설정을 추가하지 않는다.
14. `원본 테스트 대화`에 `최종 개선 프롬프트`의 규칙을 임의로 적용하지 않고, 입력된 `원본 프롬프트`와 `원본 인트로 대화`를 그대로 적용한다.
15. `개선 테스트 대화`에 `원본 프롬프트`의 지시를 별도로 추가하지 않고, 입력된 `최종 개선 프롬프트`와 `최종 개선 인트로 대화`를 그대로 적용한다.
16. 테스트 대화 안에 분석, 설명, 평가, 점수와 규칙 준수 여부를 작성하지 않는다.
17. 문제를 더 잘 해결하기 위해 각 원본 및 개선 프롬프트에 없는 추가 규칙을 임의로 적용하지 않는다.
18. `장기 대화 테스트`에서 모델이 생성하는 후속 사용자 입력은 현재 대화에 자연스럽게 반응하는 짧은 대사 또는 행동으로 작성한다.
19. `후속 사용자 입력`을 통해 프롬프트에 없는 인물, 사건, 관계와 설정을 새로 추가하지 않는다.
20. `후속 사용자 입력`이 특정한 결과를 의도적으로 유도하거나 원본 또는 개선 테스트 대화에 유리하게 작성되지 않게 한다.
21. 같은 번호의 `원본 테스트 대화`와 `개선 테스트 대화`에는 동일한 `후속 사용자 입력`의 문장, 의미와 순서를 적용한다.
22. `장기 대화 테스트`를 생성하기 전에 `테스트 사용자 입력`, `원본 인트로 대화`, `최종 개선 인트로 대화`에서 사용자의 발화자 이름을 확인한다.
23. 사용자의 이름이 확인된 경우 첫 번째 `테스트 사용자 입력`과 모든 `후속 사용자 입력`의 발화자 이름으로 해당 이름을 사용하며, 앞에 `사용자 :`를 추가하지 않는다.
24. `테스트 사용자 입력`이 이미 `인물 이름 : 대사` 형식이라면 인물 이름과 대사 본문을 분리하여 출력하고, 인물 이름을 중복해서 작성하지 않는다.
25. 사용자의 이름을 명확하게 확인할 수 없는 경우에만 발화자 이름으로 `사용자`를 사용한다.
26. 같은 번호의 `원본 테스트 대화`와 `개선 테스트 대화`에는 후속 사용자 입력의 발화자 이름, 문장, 의미와 순서를 동일하게 적용한다.

## 1. 테스트 입력 적용

`원본 테스트 대화`를 생성할 때 다음 순서로 대화의 시작 상태를 구성한다.

1. `원본 프롬프트`
2. `원본 인트로 대화`
3. `테스트 직전 대화 맥락`
4. `테스트 사용자 입력`

`개선 테스트 대화`를 생성할 때 다음 순서로 대화의 시작 상태를 구성한다.

1. `최종 개선 프롬프트`
2. `최종 개선 인트로 대화`
3. `테스트 직전 대화 맥락`
4. `테스트 사용자 입력`

`테스트 직전 대화 맥락`이 입력되지 않은 경우, `원본 테스트 대화`는 `원본 인트로 대화` 직후에 `테스트 사용자 입력`이 이어진 것으로 판단하고, `개선 테스트 대화`는 `최종 개선 인트로 대화` 직후에 `테스트 사용자 입력`이 이어진 것으로 판단한다.

`테스트 직전 대화 맥락`이 입력된 경우에는 해당 맥락의 마지막 발화 다음에 `테스트 사용자 입력`이 들어온 것으로 판단한다.

`테스트 직전 대화 맥락`에는 문제가 발생했던 응답 자체를 포함하지 않는다. 테스트하려는 사용자 입력이 등장하기 직전까지의 대화만 맥락으로 사용한다.

### 장기 대화 테스트 적용

`개선 요청 사항`이 다음과 같이 여러 응답이나 전체 대화의 흐름을 확인해야 하는 문제라면 `장기 대화 테스트`를 적용한다.

- 스토리 전개가 너무 느리거나 빠름
- 캐릭터의 성격이나 말투가 대화가 길어질수록 달라짐
- 인물 관계가 너무 빠르게 또는 느리게 변화함
- 이전 사건, 약속이나 대화를 시간이 지나면서 기억하지 못함
- 동일한 표현, 행동이나 갈등이 여러 턴에 걸쳐 반복됨
- 사용자의 선택이 이후 전개나 관계에 반영되지 않음
- 사용자에게 대화 턴을 주지 않고 캐릭터들끼리 대화를 계속함
- 그 밖에 하나의 응답만으로 개선 여부를 판단하기 어려운 문제

`장기 대화 테스트`에서는 다음 순서로 대화를 생성한다.

1. `테스트 사용자 입력`을 첫 번째 사용자 입력으로 사용한다.
2. 첫 번째 대화를 생성한다.
3. 직전 대화에 자연스럽게 이어지는 `후속 사용자 입력`을 모델이 생성한다.
4. 해당 `후속 사용자 입력`에 대한 다음 대화를 생성한다.
5. 같은 방식을 반복하여 `후속 사용자 입력`과 대화로 구성된 총 8라운드의 대화를 완성한다.

각 테스트 번호에 사용할 후속 사용자 입력 7개를 먼저 내부적으로 정한다.

- `원본 테스트 대화 1`과 `개선 테스트 대화 1`에는 동일한 `후속 사용자 입력` 7개를 사용한다.
- `원본 테스트 대화 2`와 `개선 테스트 대화 2`에는 동일한 `후속 사용자 입력` 7개를 사용한다.
- `원본 테스트 대화 3`과 `개선 테스트 대화 3`에는 동일한 `후속 사용자 입력` 7개를 사용한다.

테스트 번호가 다르면 자연스러운 생성 편차를 확인할 수 있도록 `후속 사용자 입력`이 서로 달라도 된다. 다만 모든 대화는 동일한 첫 번째 `테스트 사용자 입력`과 동일한 시작 상태에서 출발해야 한다.

`원본 테스트 대화`와 `개선 테스트 대화`의 대화가 달라 동일한 `후속 사용자 입력`이 문맥상 다소 어색해지더라도, 비교 조건을 유지하기 위해 `후속 사용자 입력`의 핵심 문장, 의미와 행동을 변경하지 않는다.

## 2. 동일 입력 유지

모든 원본 및 개선 테스트 대화는 정확히 같은 `테스트 사용자 입력`으로 시작해야 한다.

다음과 같이 테스트 조건을 변경하지 않는다.

- 첫 번째 사용자의 대사를 더 구체적으로 다시 작성
- 첫 번째 사용자 입력에서 생략된 감정이나 행동을 임의로 보충
- 첫 번째 사용자 입력의 의도를 다른 방향으로 해석
- 테스트 대화마다 서로 다른 첫 번째 사용자 입력을 가정
- 대화를 다양하게 만들기 위해 앞선 상황을 변경
- 등장인물의 위치, 관계나 감정 단계를 임의로 변경

`테스트 사용자 입력`이 짧거나 침묵, 말줄임표와 단답으로 구성되어 있어도 그대로 사용한다. 부족한 의미를 임의로 채워 새로운 사건을 만들지 않는다.

`장기 대화 테스트`의 `후속 사용자 입력`은 다음 기준을 지킨다.

- 직전 캐릭터 응답에 자연스럽게 반응한다.
- 대화를 이어갈 수 있는 짧은 대사나 행동으로 작성한다.
- 사용자의 성격, 관계와 행동을 임의로 확정하지 않는다.
- 프롬프트에 없는 정보를 질문이나 진술의 형태로 추가하지 않는다.
- 갈등을 의도적으로 해결하거나 악화시키지 않는다.
- 관계 변화, 성격 변화와 스토리 진행 속도를 특정 방향으로 강제하지 않는다.
- 캐릭터가 선택하고 반응할 수 있는 여지를 남긴다.

## 3. 독립 대화 생성

각 테스트 대화는 동일한 시점에서 새롭게 시작한다.

예를 들어 `원본 테스트 대화` 1에서 인물이 방을 나갔더라도, `원본 테스트 대화` 2에서는 그 사건이 일어나지 않은 원래 시작 상태에서 다시 대화를 생성한다. `개선 테스트 대화`도 같은 방식으로 각각 독립적으로 생성한다.

`원본 테스트 대화`에서 발생한 사건을 `개선 테스트 대화`의 선행 사건으로 취급하지 않으며, `개선 테스트 대화` 역시 `원본 테스트 대화`에 이어지는 대화로 작성하지 않는다.

`장기 대화 테스트`에서는 하나의 테스트 대화 안에서만 이전 라운드의 사건, 대사, 감정과 관계 변화를 이어서 반영한다. 다른 번호의 테스트 대화에는 해당 내용을 이어서 사용하지 않는다.

각 테스트 대화를 생성할 때 다음을 지킨다.

- 다른 테스트 대화의 내용을 기억하거나 참조하지 않는다.
- 다른 테스트 대화에서 사용한 사건을 이미 발생한 사실로 취급하지 않는다.
- 다른 테스트 대화의 대사에 답하지 않는다.
- 다른 테스트 대화와 다른 결과를 만들기 위해 설정을 과장하지 않는다.
- `단일 대화 테스트`의 경우 동일한 사용자 입력에 대한 완결된 단일 대화로 작성한다.
- `장기 대화 테스트`의 경우 동일한 사용자 입력에서 시작하여 총 8라운드 동안 이어지는 연속된 대화로 작성한다.

`원본 인트로 대화`에 나타난 문장을 그대로 반복하기보다, 같은 설정과 문체를 유지하며 다음 반응을 생성한다.

`장기 대화 테스트`에서도 `원본 인트로 대화`의 시작 상황과 관계를 기준으로 삼되, 이후 라운드에서 발생한 사건과 변화는 같은 테스트 대화 안에서 순서대로 누적한다.

## 6. 대화 간 자연스러운 차이

같은 그룹의 테스트 대화들은 동일한 조건에서 생성되지만 문장과 행동이 완전히 같을 필요는 없다.

다음과 같은 차이는 허용한다.

- 설정에 부합하는 대사의 구체적인 표현
- 선택 가능한 습관적 행동 중 하나의 사용
- 같은 관계 단계 안에서 가능한 짧은 반응 차이
- 장면을 이어가는 행동의 순서
- 캐릭터가 먼저 반응하는 순서
- 테스트 번호별 후속 사용자 입력의 구체적인 표현과 행동

다음과 같은 차이는 허용하지 않는다.

- 같은 그룹의 테스트 대화마다 캐릭터의 성격이 달라짐
- 현재 관계 단계가 달라짐
- 한 대화에서만 새로운 가족이나 사건이 등장함
- 한 대화에서만 금지된 표현이나 행동을 의도적으로 사용함
- 다양성을 위해 한 대화를 지나치게 길거나 짧게 만듦
- 서로 다른 장르나 문체로 작성함
- 한 대화에서만 관계를 급격하게 변화시킴
- 같은 번호의 원본 테스트 대화와 개선 테스트 대화에 서로 다른 후속 사용자 입력을 사용함

`원본 테스트 대화`와 `개선 테스트 대화`를 의도적으로 비슷하게 만들거나 다르게 만들지 않는다. 각 원본 및 개선 테스트 대화 그룹에 입력된 프롬프트와 인트로 대화를 그대로 적용하여 자연스럽게 생성한다.

## 7. 테스트 대화 개수

`원본 테스트 대화`를 3개 생성한다.

`개선 테스트 대화`를 3개 생성한다.

각 테스트 대화에는 생성 순서에 따라 다음 제목을 붙인다.

- 원본 테스트 대화 1
- 원본 테스트 대화 2
- 원본 테스트 대화 3
- 개선 테스트 대화 1
- 개선 테스트 대화 2
- 개선 테스트 대화 3

단일 대화로 판단할 수 있는 개선 요청이라면 각 테스트 대화에는 `테스트 사용자 입력`에 대한 대화 1개만 포함한다.

장기 대화가 필요한 개선 요청이라면 각 테스트 대화에는 첫 번째 `테스트 사용자 입력`을 포함하여 총 8개의 사용자 입력과 8개의 대화를 포함한다.

## 8. 출력 형식 유지

각 테스트 대화는 캐릭터챗 서비스에서 실제로 생성되는 대화 원문 형태로 작성한다.

`원본 테스트 대화`는 `원본 인트로 대화`와 `테스트 직전 대화 맥락`에서 사용하는 형식을 유지한다.

`개선 테스트 대화`는 `최종 개선 인트로 대화`와 `테스트 직전 대화 맥락`에서 사용하는 형식을 유지한다.

예시:

- 캐릭터의 대사는 `인물 이름 : 대사` 형태로 작성한다.
- 발화자 이름이 없는 문장은 내레이션으로 작성한다.
- 대사와 내레이션 사이의 줄바꿈 방식을 유지한다.
- 테스트 대화 내부에 제목, 분석 항목과 규칙 설명을 넣지 않는다.
- 같은 그룹의 테스트 대화 사이에만 지정된 구분선을 사용한다.

### 장기 대화 테스트의 사용자 발화자 이름 결정

`장기 대화 테스트`에서는 첫 번째 `테스트 사용자 입력`과 모델이 생성한 모든 `후속 사용자 입력`에 사용할 사용자 발화자 이름을 먼저 하나로 확정한다.

사용자 발화자 이름은 다음 우선순위로 판단한다.

1. `테스트 사용자 입력`이 `인물 이름 : 대사` 형식이면 해당 인물 이름을 사용한다.
2. `테스트 사용자 입력`에 이름이 없으면 `원본 인트로 대화`와 `최종 개선 인트로 대화`에서 사용자 역할의 발화자 이름을 확인한다.
3. `원본 인트로 대화`와 `최종 개선 인트로 대화`에서 동일한 사용자 이름이 확인되면 해당 이름을 사용한다.
4. 한쪽 인트로 대화에만 사용자 이름이 표시되어 있더라도, 해당 인물이 사용자 역할임이 명확하고 다른 입력과 충돌하지 않으면 그 이름을 사용한다.
5. 사용자 역할의 이름이 없거나, 두 인트로 대화의 이름이 서로 다르거나, 사용자와 캐릭터를 명확히 구분할 수 없으면 `사용자`를 사용한다.

확정한 사용자 발화자 이름은 모든 `원본 테스트 대화`와 `개선 테스트 대화`에서 동일하게 유지한다.

`테스트 사용자 입력`이 이미 `인물 이름 : 대사` 형식이라면 이를 다시 다른 발화자 이름 아래에 넣지 않는다. 발화자 이름과 대사 본문을 분리한 뒤 다음과 같이 한 번만 출력한다.

좋은 예:

정그루 : 아.. 그랬었나. 미안, 까먹었어.

이호 : “오늘 몇 시에 끝나.”

정그루 : 나 오늘 촬영 준비 때문에 늦게 끝나. 먼저 들어가.

나쁜 예:

사용자 : 정그루 : 아.. 그랬었나. 미안, 까먹었어.

이호 : “오늘 몇 시에 끝나.”

사용자 : 정그루 : 나 오늘 촬영 준비 때문에 늦게 끝나. 먼저 들어가.

`장기 대화 테스트`에서는 모델이 생성한 `후속 사용자 입력`을 캐릭터 응답과 구분할 수 있도록 `확정한 사용자 발화자 이름 : 대사 또는 행동` 형식으로 작성한다.

첫 번째 `테스트 사용자 입력`도 같은 발화자 이름과 형식으로 표시한다.

같은 번호의 `원본 테스트 대화`와 `개선 테스트 대화`에는 발화자 이름까지 포함하여 동일한 후속 사용자 입력을 사용한다.

원본 서비스 형식에 별도의 규칙이 있다면 해당 형식을 우선한다.

## 9. 출력 전 자체 검증

최종 결과를 출력하기 전에 각 테스트 대화를 내부적으로 확인한다. 검증 결과는 출력하지 않는다.

### 테스트 유형 검증

- `개선 요청 사항`이 하나의 응답으로 확인 가능한지  여러개의 대화에서 흐름이 필요한지 올바르게 판단했는가?
- 장기적인 변화와 누적을 확인해야 하는 문제에 `단일 테스트 대화`만 생성하지 않았는가?
- 단일 대화로 충분한 문제를 불필요하게 8라운드까지 확장하지 않았는가?
- `장기 대화 테스트`가 정확히 8라운드로 구성되었는가?

### 동일 조건 검증

- 모든 원본 및 개선 테스트 대화가 동일한 첫 번째 사용자 입력에 답하는가?
- 모든 원본 및 개선 테스트 대화가 동일한 직전 시점에서 시작하는가?
- 앞 테스트 대화의 사건이 다음 대화에 이어지지 않았는가?
- `원본 테스트 대화` 그룹 안에서 `원본 프롬프트`나 관계 조건을 다르게 적용하지 않았는가?
- `개선 테스트 대화` 그룹 안에서 `개선 프롬프트`나 관계 조건을 다르게 적용하지 않았는가?
- `원본 테스트 대화` 그룹과 `개선 테스트 대화` 그룹 사이에서 프롬프트와 인트로 대화 외의 테스트 조건이 달라지지 않았는가?
- 같은 번호의 `원본 테스트 대화`와 `개선 테스트 대화`에 동일한 후속 사용자 입력이 적용되었는가?

### 후속 사용자 입력 검증

- `후속 사용자 입력`이 직전 대화에 자연스럽게 이어지는가?
- `후속 사용자 입력`이 새로운 설정이나 사건을 임의로 추가하지 않았는가?
- `후속 사용자 입력`이 `원본 테스트 대화` 또는 `개선 테스트 대화`에 유리한 결과를 강제하지 않는가?
- `후속 사용자 입력`이 지나치게 길어 대화의 문제를 가리지 않는가?

### 원본 테스트 대화 설정 검증

- 인물의 성격과 말투가 `원본 프롬프트`와 일치하는가?
- 현재 인물 관계와 관계 단계가 유지되는가?
- `원본 프롬프트`에 없는 설정을 추가하지 않았는가?
- 인물별 정보가 서로 섞이지 않았는가?
- `최종 개선 프롬프트`에만 존재하는 규칙을 `원본 테스트 대화`에 추가하지 않았는가?

### 개선 테스트 대화 설정 검증

- 인물의 성격과 말투가 `최종 개선 프롬프트`와 일치하는가?
- 현재 인물 관계와 관계 단계가 유지되는가?
- `최종 개선 프롬프트`에 없는 설정을 추가하지 않았는가?
- 인물별 정보가 서로 섞이지 않았는가?
- `원본 프롬프트`에만 존재하는 규칙을 `개선 테스트 대화`에 추가하지 않았는가?

### 출력 규칙 검증

- 각각 `원본 프롬프트`와 `최종 개선 프롬프트`에 명시된 전역 출력 규칙을 지켰는가?
- 문장 수, 문단 수와 글자 수 제한이 있다면 각 캐릭터 응답에서 지켰는가?
- 대사와 내레이션의 비율이 각각 `원본 프롬프트`와 `최종 개선 프롬프트`의 기준에 맞는가?
- 각각 `원본 프롬프트`와 `최종 개선 프롬프트`에서 금지한 출력 방식이 나타나지 않았는가?
- 인물의 습관을 한 대화에 과도하게 나열하지 않았는가?
- `장기 테스트 대화`가 진행되는 동안에도 동일한 규칙을 계속 적용했는가?

### 테스트 유효성 검증

- 문제를 숨기기 위해 대화를 비정상적으로 짧게 만들지 않았는가?
- 대화를 서로 다르게 보이게 하려고 설정을 변경하지 않았는가?
- 각 대화가 실제 서비스에서 생성될 법한 자연스러운 대화인가?
- 대화 외에 평가나 해설이 포함되지 않았는가?
- `원본 테스트 대화`를 의도적으로 나쁘게 만들거나 `개선 테스트 대화`를 의도적으로 좋게 만들지 않았는가?
- 스토리 진행, 성격 유지와 관계 변화처럼 누적 관찰이 필요한 문제가 실제로 드러날 수 있을 만큼 대화가 이어졌는가?

기준을 충족하지 못한 테스트 대화가 있으면 해당 테스트 대화 그룹의 동일한 입력 조건을 유지한 채 다시 생성한 후 최종 테스트 대화만 출력한다.

## 출력 규칙

1. `원본 테스트 대화` 3개를 먼저 출력한다.
2. 그 다음 `개선 테스트 대화` 3개를 출력한다.
3. 각 테스트 대화는 독립적인 결과로 작성한다.
4. 같은 그룹의 각 대화 사이에는 `=====` 구분선을 한 번만 작성한다.
5. `원본 테스트 대화` 그룹과 `개선 테스트 대화` 그룹 사이에는 `--------` 구분선을 한 번만 작성한다.
6. 프롬프트와 인트로 대화를 다시 출력하지 않는다.
7. `단일 대화 테스트`에서는 `테스트 사용자 입력`을 다시 출력하지 않는다.
8. `장기 대화 테스트`에서는 대화 흐름을 확인할 수 있도록 첫 번째 `테스트 사용자 입력`과 모델이 생성한 `후속 사용자 입력`을 대화와 함께 출력한다.
9. 생성 과정, 판단 근거, 평가와 부연 설명을 출력하지 않는다.
10. 대화별 점수, 성공 여부와 규칙 준수 여부를 표시하지 않는다.
11. 각 테스트 대화에는 테스트 대화 원문만 작성한다.
12. 각 테스트 대화 그룹의 첫 번째 대화 앞과 마지막 대화 뒤에는 `=====`를 작성하지 않는다.
