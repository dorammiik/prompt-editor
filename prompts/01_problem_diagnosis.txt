
나는 캐릭터챗에서 발생한 문제 현상을 분석하고, 해당 문제를 유도한 원본 프롬프트의 원인을 진단하려고 한다.

아래의 `개선 요청 사항`, `원본 프롬프트`, `원본 인트로 대화`, `원본 대화`를 분석하여 문제를 측정 가능한 기준으로 구조화하고, 원본 프롬프트와 인트로 대화 중 문제 현상을 유도했을 가능성이 있는 부분을 찾아라.

이 단계에서는 개선된 프롬프트나 개선된 대화를 작성하지 않는다. 문제 현상과 원인을 정확히 진단하는 데 집중한다.

## 분석 원칙

1. `원본 대화`는 실제로 발생한 문제 현상을 확인하는 근거로 사용한다.
2. `원본 프롬프트`와 `원본 인트로 대화`는 문제 현상을 유도한 원인을 찾는 대상으로 사용한다.
3. `원본 대화`에서 문제가 나타났다는 이유만으로 `원본 프롬프트`에 원인이 있다고 단정하지 않는다.
4. `원본 프롬프트`의 특정 문장이나 구성 방식이 모델의 출력에 어떤 영향을 줄 수 있는지 설명할 수 있을 때만 원인으로 선정한다.
5. 단순히 개선 규칙이 없다는 점뿐 아니라, 문제 현상을 적극적으로 유도하는 표현과 정보도 찾아야 한다.
6. 동일한 원인을 표현만 바꾸어 중복으로 제시하지 않는다.
7. 사용자의 `개선 요청 사항`과 직접 관련 없는 캐릭터 설정이나 세계관 설정은 원인으로 선정하지 않는다.
8. 근거가 부족한 경우에는 임의로 추측하지 말고 근거 부족이라고 표시한다.

## 1. 문제 현상

`개선 요청 사항`과 `원본 대화`를 비교하여 다음 내용을 도출한다.

### 개선 대상

사용자가 고치고 싶은 캐릭터, 관계, 설정, 대사, 내레이션 또는 표현 방식을 작성한다.

`개선 대상`은 반드시 한 단어나 하나의 항목으로 제한하지 않는다. 사용자의 요청이 여러 대상을 포함하면 서로 다른 대상을 최대 3개까지 분리한다.

사용자의 표현이 구체적이면 의미를 임의로 넓히거나 상위 개념으로 바꾸지 않는다.

`개선 대상`의 예시는 다음과 같다.

예시:

- 내레이션
- 독현과 지아의 관계
- 설정에 없는 가족 관계
- 캐릭터 대사 및 내레이션의 표현
- 독현의 말투
- 다윗과 지아의 관계 변화
- 학교와 저택의 세계관 설정
- 금기 설정 준수 여부

### 문제 현상

`원본 대화`에서 실제로 나타난 문제를 관찰 가능한 형태로 작성한다.

“너무 길다”, “어색하다”, “캐릭터답지 않다”처럼 추상적으로 작성하지 않는다. 어떤 출력이 얼마나 자주, 어떤 방식으로 나타났는지 구체적으로 설명한다.

예시:

- 응답 전체에서 내레이션 문장과 문단이 과다하게 사용됨
- 동일한 감정을 여러 신체 반응과 비유로 반복 설명함
- 캐릭터가 설정된 말투보다 길고 설명적인 문장을 반복함

## 2. 개선 목표

`문제 현상`을 줄였는지 이후 결과에서 확인할 수 있도록 `개선 목표`를 측정 가능한 기준으로 작성한다.

`개선 목표`는 최대 4개로 제한한다.

좋은 `개선 목표`의 예시:

- 하나의 응답 전체에서 내레이션은 최대 3문장
- 내레이션 블록은 최대 2개
- 대사의 글자 수가 내레이션의 글자 수보다 많음
- 한 응답에서 묘사하는 신체 반응은 최대 2개

나쁜 `개선 목표`의 예시:

- 내레이션을 적당히 줄인다
- 더 자연스럽게 작성한다
- 몰입감 있게 개선한다

사용자가 `개선 요청 사항`에서 구체적인 수치를 제시하지 않았다면 `원본 대화`의 문제 정도를 기준으로 현실적인 수치를 설정한다.

## 3. 금지 사항

`문제 현상`을 직접 발생시키거나 악화시키는 출력 방식을 `금지 사항`이라고 하며, 최대 5개까지 작성한다.

각 `금지 사항`은 모델이 실행 여부를 판단할 수 있는 구체적인 행동 단위로 작성한다.

예시:

- 동일한 감정을 다른 표현으로 두 번 이상 설명
- 한 응답에서 여러 인물의 내면을 차례로 해설
- 사용자의 침묵을 긴 심리 묘사로 확대
- 대사 사이마다 내레이션을 반복 삽입
- 장면의 긴장감을 과장된 비유로 직접 평가

## 4. 원본 프롬프트 문제 원인

`원본 프롬프트`와 `원본 인트로 대화`에서 `문제 현상`을 유도했을 가능성이 있는 부분을 찾는다.

다음 유형을 우선적으로 확인하되, 실제 `원본 프롬프트`에 근거가 있을 때만 원인으로 선정한다.

- `문제 현상`을 제한하는 구체적인 규칙이 없음
- “짧게”, “자연스럽게”, “적절하게”처럼 기준이 모호함
- `문제 현상`을 유도하는 감정, 행동, 묘사 후보가 지나치게 많음
- 여러 인물의 내면과 감정을 모두 상세히 설명하도록 유도함
- 습관적인 행동이 선택 가능한 예시가 아니라 매번 반영해야 하는 규칙처럼 작성됨
- 세계관이나 캐릭터 설명이 감정 해설과 심리 묘사 중심으로 구성됨
- 서로 다른 규칙이 충돌하거나 우선순위가 불명확함
- 원하는 형식보다 원하지 않는 형식의 예시가 더 강하게 제시됨
- `원본 인트로 대화`에서 문제되는 출력 리듬이나 문체가 반복됨
- 분량, 문장 수, 문단 수, 대사 비율 등 측정 가능한 제한이 없음

다음 내용은 원인으로 선정하지 않는다.

- `원본 대화`에서만 나타났고 `원본 프롬프트`나 `원본 인트로 대화`에서 근거를 찾을 수 없는 현상
- 사용자가 개선하려는 `개선 요청 사항`과 관계없는 설정
- 캐릭터의 핵심 정체성을 구성하므로 삭제할 수 없으며, `개선 요청 사항`과도 직접적인 관련이 없는 정보
- 서로 같은 의미를 가진 중복 원인
- 모델 생성의 일반적인 불확실성만으로 설명되는 내용

각 원인은 반드시 한 문장으로 요약한다.

캐릭터의 핵심 설정 자체가 아니라, 해당 설정이 작성된 방식이나 반복 정도가 문제라면 이를 구분해서 설명한다.

예시:

- 잘못된 분석: “지아가 독현을 두려워하는 설정이 문제다.”
- 올바른 분석: “지아의 공포를 나타내는 행동 후보가 여러 항목에 반복되어, 매 응답에서 여러 신체 반응을 동시에 묘사하도록 유도할 수 있다.”
